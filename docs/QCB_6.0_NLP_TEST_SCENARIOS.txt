FINDINGS BEHIND THE GAPS
------------------------------------------------------------
A. Scenarios 20-21: the QA matcher compares only the 20 nearest questions by embedding. The QA
   pairs are templated (Assets/Liabilities x inside/outside Qatar x many rows), so near-identical
   questions crowd the top 20 and the exact question ranks about 52nd. It matches only with a
   shortlist of 100 (DV_NLP_QA_PREFILTER_TOP_N, no index rebuild needed). In a 300-question
   sample 293 matched and 7 did not: a small but real miss rate on near-identical rows.
B. Scenario 26: 'CIMS_ROR' does not exist in this tenant's returns, so it is not flagged as an
   unindexed return, and the query is answered from F010 at 0.91 confidence.
C. Scenarios 12, 15, 16: return identity is inferred only after ranking tables across all returns,
   so wrong or over-confident picks are possible. Return-first resolution addresses this.
D. Scenarios 7, 9, 11, 13, 16, 19: even when the top table is right, the LLM is shown tables
   from all four returns, not only the right one.
E. qcb_f015_bank_cap_base cannot be queried: it is in the index but not in return 4092's
   TableMapping.xml (repository configuration).
